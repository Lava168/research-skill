# 重建与检查

## 1. 原尺寸坐标

从选定 PDF 页读取可视页宽、高。PDF 坐标使用 pt，绘制到 Artifact Tool 时乘以 `4/3` 转为 CSS px，写入 PPT 时等价于每 pt 12,700 EMU。保留纸面空白、页眉和页脚，除非用户明确要求只截取图内区域。原尺寸模式不自动改成 16:9、4:3 或 A4。

## 2. 文字与矢量

通过 PyMuPDF 的扩展 drawing 列表提取路径和组状态，保留直线、三次贝塞尔、矩形、颜色、描边、透明度与绘制顺序。部分凸裁切可以转换为可编辑的分段路径；遇到不能可靠表达的复合/非凸裁切，保留警告并配置局部处理。

按 PDF span 保存文字内容、原点基线、字号、颜色、透明度、旋转方向和独立的上下标 span。原本隐藏的文字保持透明，避免将隐藏 OCR 层突然显示出来。字体映射与字符间距修正用于接近源图宽度。默认保持已验证流程中的“文字置于艺术图上方”策略，记录在 `build_report.json`；有遮挡关系的 PDF 必须检查是否适用。

将路径转成 PowerPoint 原生 custom geometry，将文字转成独立文本框。记录每个对象的类型、面板、源边界及名称，以便分组和验证。

## 3. 图片

按实际图片绘制操作定位嵌入图片，排除伪图像和已合成区域。将 RGB 与原始软蒙版组合，保留源像素尺寸。页面裁切与图片软蒙版是两件事；仅提取 xref 的图片字节可能带出 PDF 中实际隐藏的标题、坐标轴或边框。

需要拆开拼图时使用整数像素边界，并验证每个像素恰好覆盖一次、重新拼接后与原图一致。PPT 中的摆放边界从原图像素坐标按精确比例换算，避免分块后出现接缝。

特殊灰度阴影可按配置在原像素尺寸评估原 PDF Form，完整合成软蒙版、组透明度与 Multiply，再用黑色 RGBA 表示有效 alpha。已合成有效透明度的图片在 PPT 中放置为 100%，不重复乘一次透明度。

透明裁切后如实际 PPT 渲染产生浅灰边框，可将图合成到已知背景色。该操作只在固定背景和正确层级条件下使用；同位置有背景内容时先检查遮挡。保留透明原件与处理记录，最终边框是否消失以 PPT 的渲染结果为准。

复杂渐变插图使用局部 `raster_regions`。先从临时 PDF 副本移除文字，再渲染该小区域；将文字另行保留为可编辑对象。不要在交付说明中把这个区域描述为逐个矢量元素可编辑。

## 4. 分组与层级

在 OOXML 中为面板生成原生 `p:grpSp`，保持子对象坐标，并恢复线帽、连接样式与图片描述。解除不必要的移动、选择和文字编辑锁。

组只能占据一个层级位置。若面板之间相互交叠且对象绘制顺序交错，强行分组会改变遮挡。构建器检查此风险并在报告中说明跳过的分组；此时保留正确的平面对象顺序，再根据可见内容调整分组设计。

## 5. 验证与交付边界

自动检查包括：PPTX 包与 XML、内部关系、图片资源、唯一对象 ID、单页尺寸、文字内容多重集、各类对象数量、原生分组数量，以及最终文件与候选文件的 SHA-256 一致性。Presentations 校验工具另外执行格式、布局、字体策略与 Artifact Tool 导入检查。

自动检查不能证明字体外观、渐变、alpha 边缘、图层遮挡或图片细节与原页完全一致。用 LibreOffice 或其他实际演示文稿渲染器输出预览，至少查看以下局部：

- 上下标、旋转标签、特殊符号与文字截断。
- 热图色块、坐标轴、数据点和误差线。
- 显著性星号与括号之间的间距。
- 页面裁切边缘、透明边缘、拼图接缝和比例尺。
- 分组后的面板层级与缩放位置。

有意保留为位图的对象仍可在 PPT 中移动、缩放、替换；其像素不因此成为可单独编辑的细胞或数据点。矢量统计图不等于附带可重新计算的原始数据表。明确说明实际做到的编辑范围。
